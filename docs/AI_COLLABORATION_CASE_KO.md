# KiriKiri2 macOS ARM64: AI 협업 사례와 최종 상태

정리·재검증일: 2026-10-13, 한국 시간. ChatGPT Contributor Survey에서 사용할 사실 기반 기록입니다.
근거는 사용자 요청·오류 보고·테스트 회신, 로컬 Git 변경 이력, 빌드/CTest 결과,
macOS 충돌 기록과 실행 창 확인입니다. 설문 제출 자체는 이 작업에 포함되지 않습니다.
대화 전문, 게임 화면·대사, 개인 경로, 인증 정보는 수록하지 않습니다.

## 목표와 사용자 입력

사용자는 공개 KrKr2 소스를 Apple Silicon 맥에서 빌드하고 실제 게임을 실행할 것을 요청했습니다.
README의 macOS 프리셋을 따르고 필요한 도구를 준비하되, 원본 저장소를 보존하고
수정은 별도 작업 폴더·브랜치에 남기라는 조건을 제시했습니다.
이후 누락된 shrinkCopy 기능, 창 조절·전체화면 요구, 메뉴 클릭 시 종료,
읽기 어려운 최근 파일명, 시스템 메뉴 무반응, 특정 회상 전환에서의 종료를 보고했습니다.
오류 화면과 재현 상황, 대상 폴더 정보도 제공했습니다.
최종 저장소의 비공개 공개 범위를 선택했고 GitHub 인증·본인 확인은 직접 수행했습니다.

## AI가 수행한 작업과 이력

아래 해시는 **로컬 원본 이력**입니다. GitHub에는 리소스를 제외해 정리한 이력을 올리므로
GitHub 커밋 해시는 다릅니다. 변경 메시지와 파일 내용으로 대응 관계를 확인할 수 있습니다.

| 단계 | AI 작업 | 로컬 이력·검증 |
|---|---|---|
| 최초 빌드 | 도구·vcpkg·환경 변수 준비, macOS Debug 프리셋 빌드, arm64 앱 확인 | 초기 테스트 5개, 앱 실행 확인 |
| shrinkCopy 누락 | 공개 플러그인을 네이티브로 통합, LP64 픽셀 폭 및 누적 계산 수정 | `aa50f7c`, 관련 회귀 테스트 추가, 사용자 진행 확인 |
| 창·전체화면 | 창 리사이즈, 비율 유지, 네이티브 전체화면과 게임 속성 연동, 위치 복원 | `b0e5279`, 수동 창·버튼·재실행 검증 |
| 메뉴 종료·글자 깨짐 | 메뉴 목록 초기화 및 조회 실패 검사, 번들 CJK 글꼴 사용, 최근 이름 크기·시작 위치 조정 | `d1dfc89`, 메뉴·콘피그 및 파일명 표시 확인 |
| 시스템 메뉴 무반응 | 활성 상태 주기 갱신, 비활성 표시, TJS 객체 참조 유지 | `879a87f`, 무반응 자체는 재현 못함; 수정 후 사용자 정상 회신 |
| 마지막 장면 전환 종료 | TJS 실행 스택을 스레드별로 분리, 공유 객체 추적 잠금 추가 | `8bd64ef`, 전체 12개 테스트 통과 및 새 테스트 각각 20회 통과 |
| 실제 장면 검증 기록 | AI의 앱 시작 확인과 사용자의 실제 장면 확인을 구분해 문서화 | `08c0096`, 사용자 “합격!” 회신 |

## 마지막 오류: 원인, 해결 방법, 수정 파일

장면 전환 중 음성 해독 스레드는 XP3 데이터를 읽으며 별도 TJS 필터 엔진을 생성했습니다.
충돌 경로는 `VorbisWaveDecoder` → XP3 추출 필터 → `AddXP3Decoder` →
`TJSAddObjectHashRecord` → `TJSGetStackTraceString` → `GetPositionDescriptionString`입니다.
다른 기록에서는 `TJSStackTracerSetCodePointer`의 메모리 접근 오류도 확인했습니다.

TJS 디버그 스택은 프로세스 전체의 단일 포인터와 벡터였으므로,
음성 작업 스레드가 메인 스레드의 실행 프레임·코드 포인터를 읽거나 수정할 수 있었습니다.
기존 코드에서 작업 스레드가 메인 스크립트의 실행 기록을 보는 회귀 테스트가 실패했습니다.
수정 후 같은 테스트가 통과했으며, 공유 객체 추적 테이블의 동시 접근도 잠금으로 보호했습니다.
게임 데이터나 게임 호환 패치를 변경할 필요 없이 앱 내부 코드를 수정했습니다.

| 파일 | 최종 변경 |
|---|---|
| `cpp/core/tjs2/tjsDebug.cpp` | 실행 스택 포인터를 `thread_local`로 분리; 객체 추적·로그·상태 조회를 재귀 mutex로 보호 |
| `cpp/core/tjs2/tjsDebug.h` | thread-local 선언 및 잠금이 적용되는 상태 조회 함수 선언 |
| `tests/unit-tests/core/tjs2/tjsDebug-thread.cpp` | 다른 스레드의 실행 스택 누출과 동시 객체 추적을 검증하는 테스트 2개 |
| `tests/unit-tests/core/tjs2/CMakeLists.txt` | 새 테스트 실행 파일 등록 |
| `docs/MACOS_HISTORY.md` | 충돌 근거, 수정 및 사용자 검증 기록 |

## 시행착오와 인간의 개입

- 최초 빌드에서는 pkg-config 누락과 오래된 시스템 Bison 등 도구 조건을 해결해야 했습니다.
  이후 의존성의 컴파일러 식별값이 바뀌었을 때 기존 arm64 캐시를 재사용해 증분 빌드를 이어갔습니다.
- 창 복원 후 화면이 축소되는 문제를 발견해 macOS의 기준 디자인 해상도를 유지하도록 보완했습니다.
- 처음 메뉴가 열리는 것을 확인한 뒤에도 사용자가 클릭 무반응을 추가로 보고했습니다.
  AI의 성공 테스트는 모든 상황의 정상 동작을 증명하지 않았습니다.
  활성 상태 갱신과 재실행 중 어느 것이 무반응을 해소했는지는 확정하지 않았습니다.
- 동일 식별자의 앱 여러 개가 동시에 실행돼 자동 조작 대상이 혼동됐습니다.
  마지막 수정본에 별도 앱 식별자를 부여해 `krkr2-audio-fix.app`으로 구분했습니다.
- GitHub 저장소 생성·인증 완료를 소스 업로드 완료로 취급할 수 없었습니다.
  2026-10-13 조회에서 기존 비공개 저장소에는 브랜치가 없었고, 이번 업데이트에서 실제 푸시를 진행합니다.
- 사용자는 실제 사용 중 새로운 오류를 찾아 재현 정보를 제공하고, 최종 수정본의 장면 테스트를
  “합격!”으로 확인했습니다. 이 인간의 검증은 AI의 자동 회귀 테스트와 별개의 근거입니다.

## 검증 결과와 남은 범위

- 2026-10-13: 현재 소스의 MacOS Debug Build 성공, 로컬 CTest **12/12 통과**.
- ARM64 실행 파일, 최종 앱 ad-hoc 서명, macOS에서 `KrKr2 Audio Fix` 창 표시를 재확인했습니다.
- 새 스레드 테스트 2개는 2026-10-10 각각 20회 반복해 통과했습니다.
- 회상 장면 통과는 2026-10-10 사용자 검증입니다. 10월 13일에 그 장면 전체를 재플레이한 것은 아닙니다.
- 모든 게임·플러그인 호환성과 세이브 저장·복원 전체 동작은 검증하지 않았습니다.
- 메뉴 무반응의 정확한 유발 조건은 미확정입니다. 실제 장면 충돌과는 구분합니다.
- 빌드는 Debug/ad-hoc 서명 상태이며 Apple 개발자 배포 서명·공증은 수행하지 않았습니다.

## GitHub 보존과 업로드 제외 범위

대상은 기존 비공개 저장소 `Jsrmana/krkr2-macos`입니다. 원저작자 라이선스와 소스 고지는 유지합니다.
사용자의 게임, 세이브, 추출 스크립트, 개인 파일, 원시 로그, 인증정보, 도구·캐시는 포함하지 않습니다.
원본에 포함된 이미지·모션 테스트 샘플과 그 자료를 사용하는 테스트 소스도 업로드 이력에서 제외합니다.
따라서 GitHub 복제본에는 자료 의존 테스트 2개가 등록되지 않아 **10개**를 실행하며,
자료가 남아 있는 로컬 원본의 **12개 통과**와 구분해야 합니다.
로컬 원본·전체 이력을 보존하고 별도 업로드 폴더에서 정리하므로 GitHub 해시는 로컬 해시와 다릅니다.

## 설문에 사용할 요약

사용자는 macOS 앱 빌드 목표와 원본 보존 조건을 정하고, 실행 중 오류 화면·폴더 위치·장면 정보를
제공했습니다. AI는 개발 도구 준비, 네이티브 플러그인 이식, 창 기능 구현, 충돌 기록 분석,
코드 수정과 회귀 테스트를 수행했습니다. 사용자의 추가 오류 보고 때문에 처음의 빌드 성공에서
작업을 끝내지 않고 실제 게임 호환 문제를 반복적으로 좁혀갔습니다. 마지막에는 음성 해독과 게임
실행이 디버그 스택을 공유하는 앱 내부 오류를 수정했습니다. 자동 테스트와 사용자의 실제 장면
테스트를 함께 근거로 삼았으며, 미확정 메뉴 원인과 미검증 호환 범위도 기록했습니다.
