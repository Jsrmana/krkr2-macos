## shrinkCopy 오류 수정

게임 실행 중 `Member "shrinkCopy" does not exist` 오류가 발생했습니다.
원본 shrinkCopy 소스를 엔진의 내부 플러그인 등록 구조에 통합했습니다.
LP64에서 픽셀이 8바이트로 취급되지 않도록 `uint32_t`를 사용하고, 누적 계산은 `uint64_t`로 처리했습니다.
축소 테이블 할당 크기와 실패한 할당에 대한 포인터 연산도 수정했습니다.
Windows DLL을 macOS에서 직접 로드하는 방식이 아니라 소스를 arm64로 컴파일합니다.
사용자가 같은 게임을 진행하여 오류 해결을 확인했습니다.

## 창 및 전체화면

Cocos/GLFW 창의 크기 조절을 활성화하고 AppKit 전체화면과 게임의 Window.fullScreen 속성을 연결했습니다.
화면 비율과 클릭 좌표를 확인했으며, 창 프레임 저장 및 복원을 추가했습니다.
창 복원 후 UI가 한쪽으로 축소되는 문제를 발견해 macOS에서 기준 디자인 해상도를 유지하도록 수정했습니다.

수동 검증:

- 창 크기 960×672 → 720×814 → 720×654 변경(제목 표시줄 포함).
- 초록색 버튼 및 Control + Command + F로 전체화면 진입·복귀.
- 크기를 바꾼 창에서 게임 시작 및 설정 버튼 입력.
- 제공된 게임의 전체화면 체크박스로 진입·복귀.
- 종료 후 재실행하여 창 크기와 화면 배치 복원.

최종 CTest 결과: **10개 통과, 실패 0개**.
추가 테스트는 RGBA 축소 평균, 음수 pitch와 잘린 대상 영역, 확대 거부,
빠른 축소의 나머지 영역 처리, 실제 TJS 모듈 등록 및 메서드 호출을 검증합니다.
최종 앱의 ad-hoc 코드 서명도 검증했습니다.
