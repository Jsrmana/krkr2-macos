보존일: 2026-09-08 (한국 시간). 실제 빌드 및 기능 검증: 2026-09-07.

- 기준 커밋: `dca7264572a63e753c1b07ca7053513d1751ce70`
- macOS 수정 브랜치: `codex/macos-arm64-build`

## shrinkCopy 오류 수정

게임 실행 중 `Member "shrinkCopy" does not exist` 오류가 발생했습니다.
원본 shrinkCopy 소스를 엔진의 내부 플러그인 등록 구조에 통합했습니다.
LP64에서 픽셀이 8바이트로 취급되지 않도록 `uint32_t`를 사용하고, 누적 계산은 `uint64_t`로 처리했습니다.
축소 테이블 할당 크기와 실패한 할당에 대한 포인터 연산도 수정했습니다.
Windows DLL을 macOS에서 직접 로드하는 방식이 아니라 소스를 arm64로 컴파일합니다.
사용자가 같은 게임을 진행하여 오류 해결을 확인했습니다.

## 창 및 전체화면

Cocos/GLFW 창의 크기 조절을 활성화하고 AppKit 전체화면과 게임의 Window.fullScreen 속성을 연결했습니다.
화면 비율과 클릭 좌표를 확인했으며, 창 프레임 저장 및 복원을 추가했습니다.
창 복원 후 UI가 한쪽으로 축소되는 문제를 발견해 macOS에서 기준 디자인 해상도를 유지하도록 수정했습니다.

수동 검증:

- 창 크기 960×672 → 720×814 → 720×654 변경(제목 표시줄 포함).
- 초록색 버튼 및 Control + Command + F로 전체화면 진입·복귀.
- 크기를 바꾼 창에서 게임 시작 및 설정 버튼 입력.
- 제공된 게임의 전체화면 체크박스로 진입·복귀.
- 종료 후 재실행하여 창 크기와 화면 배치 복원.

최종 CTest 결과: **10개 통과, 실패 0개**.
추가 테스트는 RGBA 축소 평균, 음수 pitch와 잘린 대상 영역, 확대 거부,
빠른 축소의 나머지 영역 처리, 실제 TJS 모듈 등록 및 메서드 호출을 검증합니다.
최종 앱의 ad-hoc 코드 서명도 검증했습니다.

소스 코드, 원본 커밋 이력, 수정 이력, 빌드 및 검증 안내와 완성 앱을 보존합니다.
게임 파일, 세이브, 추출한 게임 스크립트, 개인 경로가 담긴 원시 로그,

## 2026-10-10: 게임 메뉴 종료 및 최근 파일명 표시 수정

작업 브랜치: `codex/fix-game-menu-crash` (기준: `9246f30`).

하단 도구 모음의 왼쪽 메뉴 버튼을 누르면 `ListView::removeAllItems`에서
널 포인터 접근으로 종료됐습니다. 메뉴 생성에 쓰던 `Node*` 형태의
`initFromFile`이 실제 초기화 없이 성공을 반환해 목록이 생성되지 않았습니다.
게임 메뉴에 필요한 헤더와 목록을 직접 생성·연결하고, 네이티브 메뉴 조회 실패를
검사하도록 수정했습니다. 게임이 숨김 또는 비활성으로 지정한 항목도 반영합니다.

기존 CSB 화면 파일은 앱에 없는 `DroidSansFallback.ttf`를 참조해 macOS의
시스템 글꼴 경로로 처리됐고, 글자가 색 줄무늬처럼 깨져 표시됐습니다.
macOS에서 해당 Text 위젯이 앱에 포함된 `NotoSansCJK-Regular.ttc`를 사용하도록
수정했습니다. 헤더도 글꼴 파일을 시스템 글꼴 이름으로 전달하지 않고 TTF로 로드합니다.
최근 목록은 게임 폴더명을 26 크기로, 경로와 파일명을 18 크기로 표시하고,
처음에는 게임 폴더명의 시작 부분을 보여줍니다. 긴 이름은 가로로 드래그해 확인합니다.

검증:

- `MacOS Debug Build` 증분 빌드 및 CTest **10개 통과, 실패 0개**.
- arm64 앱 번들 생성 및 ad-hoc 서명 검증.
- 제공된 게임의 타이틀과 전철 장면에서 하단 메뉴 열기, 시스템 하위 메뉴 진입,
  뒤로 가기를 확인했습니다. 전철 장면에서 콘피그 실행 및 게임 복귀도 확인했습니다.
- 런처 최근 목록의 영문·일문, 게임 메뉴의 한글이 깨짐 없이 표시됐습니다.
- 최근 목록이 제목 시작 부분을 보여주고, 가로 드래그로 뒤쪽 파일명까지 볼 수 있음을 확인했습니다.
- 세이브 슬롯 쓰기 및 저장 데이터 복원은 이번 검증에 포함하지 않았습니다.

완성 앱은 작업 공간의 `outputs/krkr2-menu-fix.app`에 별도로 두었습니다.
기존 창 크기 조절·전체화면·shrinkCopy 변경을 포함합니다.

### 시스템 항목 클릭 무반응에 대한 추가 대응

사용자는 동일 앱에서 게임 진행 중 시스템 메뉴 항목이 실행되지 않는 현상을
추가로 보고했습니다. 재검사에서는 콘피그와 로드 화면 진입이 성공해 해당
무반응을 재현하지 못했습니다. 따라서 원인이 확정됐다는 결론은 내리지 않습니다.

코드 검사에서 메뉴 행의 활성 상태를 생성 시 한 번만 읽는 문제를 발견했습니다.
게임이 이후 활성 상태를 바꾸면 반영되도록 0.1초마다 부모 항목을 포함해 갱신하고,
비활성 항목은 회색으로 표시합니다. 갱신 콜백이 사용하는 TJS 객체의 참조도 유지합니다.
기존 게임의 활성 상태 검사와 실행 허용 조건은 그대로 적용합니다.

추가 빌드와 CTest 10개 및 앱 서명 검증이 통과했습니다. 업데이트 후 사용자는
메뉴가 정상으로 실행된다고 확인했습니다. 활성 상태 갱신 또는 재실행 중 어느 것이
보고된 현상을 해소했는지는 구분되지 않았습니다.

### 장면 전환 중 음성 해독 스레드 충돌

최신 macOS 충돌 기록에서는 Vorbis 음성을 XP3에서 읽는 작업 스레드가
XP3 필터용 TJS 엔진을 생성하던 중 `TJSAddObjectHashRecord` →
`TJSGetStackTraceString` → `GetPositionDescriptionString`에서 잘못된 주소에 접근했습니다.
별도의 이전 기록에서도 `TJSStackTracerSetCodePointer`에서 충돌한 흔적이 있었습니다.

TJS의 디버그 실행 스택은 모든 스레드가 한 포인터를 공유하고 있었습니다.
작업 스레드에서 스택을 조회했을 때 메인 스레드의 활성 스크립트 기록이 보이는
회귀 테스트를 만들었으며, 기존 코드에서 실패함을 확인했습니다.
실행 스택을 `thread_local`로 분리하고, 공유 객체 추적 테이블과 로그는
재진입 가능한 잠금으로 보호했습니다. 게임 파일이나 호환 패치는 변경하지 않았습니다.

검증: 전체 CTest **12개 통과**. 새 스레드 격리·동시 객체 추적 테스트를 각각
20회 반복해 모두 통과했습니다. arm64 앱 번들과 ad-hoc 서명도 검증했습니다.
독립된 앱 식별자를 가진 `outputs/krkr2-audio-fix.app`을 제공하며,
`outputs/krkr2-menu-fix.app`에도 동일한 엔진 수정을 반영했습니다.
